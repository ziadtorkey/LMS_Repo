# Demo packages for the M4b E2E suite

**Authored by the LMS team.** Every file in these packages (manifests, HTML, JavaScript, CSS, the H5P library) was written for this project;
no third-party code, text or media is included, so there is no licence to record and they may be committed and redistributed with the repository.
They are generated by `DemoPackages.cs` (stored entries, fixed timestamps: the bytes are the same on every machine); `DemoPackageTests` proves
the committed files equal the builder, that they pass the archive reader and the real SCORM / H5P validators, and that the test ids below exist.

Regenerate (only after changing the builder): `LMS_REGEN_DEMO=1 dotnet test tests/Lms.IntegrationTests --filter Demo_files_are_regenerated`.

| File | Kind | What it is |
|---|---|---|
| `demo-scorm12.zip` | SCORM 1.2, single SCO | two pages (`index.html`, `page2.html`), `sco.js`, `style.css` |
| `demo-scorm2004.zip` | SCORM 2004 4th edition, single SCO | the same pages with the 2004 API and data model |
| `demo-h5p-quiz.h5p` | H5P | a one-question quiz in our own library `LmsDemoQuiz-1.0` (no H5P.org library, so nothing third party) |

Both SCORM packages are valid for the strict content host: no frames, no `eval`, no external address, all scripts are files of the package.

## Test ids (for the page objects)

SCORM pages (inside the player frame):

| Page | Test id | Meaning |
|---|---|---|
| both | `sco-title` | the lesson title |
| both | `sco-api-status` | `API found (SCORM 1.2)` / `API found (SCORM 2004)` / `API NOT found` |
| 1 | `sco-page-1`, `sco-next` | page 1 marker; the button commits `suspend_data=page=2` and `incomplete`, then goes to page 2 after 600 ms |
| 2 | `sco-page-2` | page 2 marker |
| 2 | `sco-score` | number input, default **85** |
| 2 | `sco-finish` | sets the score (raw, min 0, max 100; 2004 also scaled), `passed` at 60 or more else `failed` (2004: `completed` + `passed`/`failed`), commits and finishes (`LMSFinish` / `Terminate`) |
| 2 | `sco-result` | `Finished with score <n>` after finishing |

A returning learner is sent from page 1 to page 2 when `cmi.suspend_data` is `page=2` (resume without starting over).

H5P quiz (in the content frame): `h5p-demo-question`, `h5p-demo-answer-0` / `-1` / `-2` (the correct one is `-1`, "4"), `h5p-demo-submit`,
`h5p-demo-result` (`Score 1 of 1` / `Score 0 of 1`). Submitting triggers one xAPI scored statement.

## Expected platform result with the defaults

Module completion rule `Score`, minimum score 60, grading method Highest: finishing with the default 85 completes the module with score
85/100 and writes one grade event of 85; finishing with 40 does not complete it. The same holds for both SCORM versions.

## Limits to know

- The H5P package is structurally valid and passes our validator; it is meant to run in the vendored H5P player of Task 11, which is not on the
  branch that added these files, so it has not been run in a browser yet.
- The page-1 to page-2 hop waits 600 ms after its commit so the platform has the new state when page 2 loads; E2E steps should wait for
  `sco-page-2` rather than for a fixed time.
