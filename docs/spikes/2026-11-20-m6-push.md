# M6 Web Push: service-worker contract for the client (Task 8, for FE2 Task 26)

Server: Lib.Net.Http.WebPush 3.3.1 (MIT) over VAPID (RFC 8291 payload encryption, RFC 8292 VAPID). Decided by the owner on 2026-11-14.

## Subscribing

1. `GET /api/me/push/vapid-public-key` returns `{ "publicKey": "<base64url>" }`. A 404 means push is not configured: hide the switch.
2. The page registers the service worker, asks `Notification.requestPermission()` (from a user gesture), then
   `registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey: publicKey })`.
3. `POST /api/me/push-subscriptions` with `{ endpoint, p256dh, auth, deviceLabel }` (`p256dh` and `auth` are the base64url `getKey()` values; `deviceLabel` is a browser family such as "Chrome on Windows", at most 100 characters). The answer is 201 with `{ id, deviceLabel, createdAtUtc, lastSuccessUtc }`. The endpoint must be `https` and at most 600 characters; saving the same endpoint again replaces the row.
4. Record the push consent (`POST /api/me/channels/push/consent`, Task 9) with the wording version the user saw.
5. `GET /api/me/push-subscriptions` lists the caller's own rows (never the endpoint or keys); `DELETE /api/me/push-subscriptions/{id}` removes one (404 for another user's).

## Payload (at most 2 KB)

```json
{ "title": "LMS", "body": "لديك إشعار جديد · You have a new notification", "url": "/grades",
  "data": { "eventKey": "Grades.Published", "notificationId": "<outbox row id>" } }
```

The text is generic on purpose (L9, L22): no message text, grade, score or student name ever travels through a push service. `url` is always a local path (anything else becomes `/`). The worker may localise the body from `data.eventKey` with its own cached resources.

## Service worker

```js
self.addEventListener('push', e => {
  const p = e.data.json();
  e.waitUntil(self.registration.showNotification(p.title, { body: p.body, data: p, tag: p.data.eventKey }));
});
self.addEventListener('notificationclick', e => {
  e.notification.close();
  e.waitUntil(clients.openWindow(e.notification.data.url));
});
```

`userVisibleOnly: true` means every push must show a notification.

## Server behaviour worth knowing

- A 404 or 410 from the push service deletes that subscription; a row is retried on 429 and 5xx (the service's `Retry-After` wins); other 4xx fail the delivery.
- TTL is 4 hours (the push event TTL of Task 5). Without the configured key the row stays pending (`not_configured`).
- Keys are protected with Data Protection; the VAPID private key is configuration only (user-secrets or environment `Comms__Push__PrivateKey`), never a committed file.

## iOS and PWA notes

- iOS Safari delivers Web Push only to a web app added to the Home Screen (iOS 16.4+), and the permission prompt must follow a tap inside that installed app. Show an "Add to Home Screen" hint on iOS instead of the switch in a normal tab.
- There is no silent push: a push that shows nothing can get the subscription revoked.
- Chrome and Firefox on Android work in the browser; Safari on macOS needs the same user gesture.

## Generating the VAPID keys (development)

`npx web-push generate-vapid-keys`, then `dotnet user-secrets set "Comms:Push:PublicKey" <public>` and `"Comms:Push:PrivateKey" <private>` in `src/Lms.Api`. In Development the fake channel stays the only push channel, so no key is needed to run the tests.
