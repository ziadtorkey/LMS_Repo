**Goal:** Every domain event reaches people on the channels they chose (in-app always; email, SMS and Web Push per event and preference) through one queued, retried, capped delivery pipeline, with no student data or message text in SMS or push. Users hold 1:1 and group conversations under D69's safeguarding-first rules, which a client may only tighten; only participants ever read a conversation. Staff publish targeted, bilingual announcements (organization, unit, level, class, course, group; role chips; now or scheduled; pin; expiry). Users report messages and block others; Org Admins moderate a reported message and its frozen context, never a live conversation. All bilingual (ar RTL / en), isolated per client, participant and relationship.

**Architecture:** Same modular monolith. Four feature areas: **Comms** (`Domain/Comms`, `Infrastructure/Comms/{Outbox,Email,Sms,Push,Preferences}`, `Features/Comms`) owns the delivery pipeline behind the existing `INotificationPublisher`; **Messaging** (`Domain/Messaging`, `Infrastructure/Messaging`, `Features/Messaging`) with one access helper (`ConversationAccess`, the only participant check) and one policy (`IMessagingPolicy`, the only "may A message B" answer); **Announcements** (`Domain/Announcements`, `Infrastructure/Announcements`, `Features/Announcements`) with one audience resolver; **Moderation** (`Domain/Moderation`, `Infrastructure/Moderation`, `Features/Moderation`) that reads frozen report context only. The publisher's in-app path is unchanged; email, SMS and push are rows of a transactional `DeliveryOutbox` (ADR 0004 pattern) sent by a per-client dispatcher through provider interfaces with fakes. Local days (quiet hours, caps, retention) come from M5's `IClientCalendar` (`Org.TimeZone`, D64).

**Tech Stack:** unchanged. MailKit (already used) behind `IEmailProvider`; VAPID Web Push (library or hand-rolled RFC 8291/8292 with `System.Security.Cryptography`, decided in Task 8 after a license check); MySQL FULLTEXT `WITH PARSER ngram` (raw SQL in the migration); SignalR on the existing `NotificationsHub`; Hangfire through `IBackgroundJobs`. Client: a service worker for push (no new package unless Task 26 shows one is needed).

**Spec:** `docs/PRD.md` FR-NOT-01..03, FR-MSG-01..04, X-01, X-05, X-07, X-08, X-10, §3.4 row "Messaging / announcements", decisions D65–D69 (and D30 guardians, D42 relationship rules, D49 platform credentials, D64 time zone). Master plan: `docs/DEV-PLAN.md` §2 M6 items 1–5 and §4.1 push discipline. Proposals: `2026-11-17-m6-backend-proposal.md` (#613), `2026-11-17-m6-frontend-proposal.md` (#612), design `docs/design/m6-communication.md` (#615). Previous plan: `2026-11-18-m5-assessment-timetable-attendance.md`.

## Scope

**In scope**
- Delivery pipeline: transactional outbox from the publisher, per-client dispatcher with leases, typed provider results, retries with backoff, TTLs, holds (quiet hours, caps), per-client and per-recipient daily caps, suppressions, retention; account emails moved onto the outbox as transactional rows.
- Channels: email (`IEmailProvider` over MailKit + fake; signature-verified bounce/complaint webhook built against the fake relay shape), SMS (`ISmsProvider` + fake, UCS-2 segment handling; no real gateway), Web Push (VAPID, subscriptions, 404/410 cleanup).
- Preferences: catalog defaults per channel, mandatory events, effective preferences with source, contact resolver (minor rule), per-channel status, email test send, SMS/push consent record, per-client channel switches, provider status.
- Messaging: direct and group conversations, participants as the access list, messages with attachments, delete for everyone within 15 minutes, unread counts, read receipts (setting, off), search, realtime ids-only events, throttled message notifications, D69 rules matrix (narrowing only), blocks, groups under D69, allowed-recipient search, rules summary, limits read, capabilities read.
- Announcements: one bilingual store, targets and role chips, scope checks, audience preview, draft/schedule/publish/expire/withdraw, pin, attachments, recipient snapshot, fan-out through the publisher, reader feed and read state; the course board shown merged now and migrated onto the new store.
- Moderation: report with frozen context, `MessageReportUnit` scope, queue, stats, resolve actions, restrictions (list and lift), audit of every moderation read and action.
- FE for all of it (two tracks), the design landing (spec + components), QA probe suite, security review, three E2E exit demos, the comms runbook.

**Out of scope (v1 or later)**
- A real SMS gateway adapter (D68: chosen before go-live, a small follow-up task); the production email relay mapping beyond the fake relay shape (D67); a real antivirus scanner (D65); all four are **go-live prerequisites**, listed in `docs/runbook-comms.md` (Task 18), not M6 exit items.
- SMS OTP or any contact verification (D66: imported contacts trusted); email digests; message editing, reactions, threads, translation; voice/video; per-client provider credentials or templates (D49 style); native mobile push (D14); conversation export; an appeal path for moderation (D66); a guardian copy of a child's conversations (D66/D69).
- Dropping the `CourseAnnouncement` table (one release after the Task 17 migration).
